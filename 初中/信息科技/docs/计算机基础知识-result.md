# 初中学生计算机基础知识学习清单

## 一、课程定位

本学习清单面向零基础初中学生，目标不是先讲某一种编程语言，而是先建立使用计算机、理解计算机、表达问题和解决问题的基础能力，为后续学习图形化编程、Python、网页制作或机器人编程打基础。

学生学完后应能做到：

1. 认识计算机由硬件、软件、数据和网络共同组成。
2. 能熟练进行基本操作：输入、保存、查找、复制、压缩、上传、下载和备份文件。
3. 理解数据在计算机中以数字形式表示，知道二进制、位、字节和常见容量单位。
4. 能用“分解问题、找规律、设步骤、试运行、改错误”的方式解决简单任务。
5. 初步理解程序的基本结构：输入、输出、变量、顺序、分支、循环、函数和调试。
6. 具备基本的信息安全、网络安全、版权意识和负责任使用人工智能工具的意识。

## 三、建议学习顺序

### 第一阶段：会使用计算机

重点是让学生从“会点鼠标”提升到“能独立完成学习任务”。

| 课时 | 主题 | 核心任务 |
|---|---|---|
| 第 1 课时 | 计算机是什么 | 认识计算机、手机、平板、服务器的共同点 |
| 第 2 课时 | 硬件与软件 | 说清 CPU、内存、硬盘、操作系统、应用软件的作用 |
| 第 3 课时 | 桌面与窗口操作 | 会打开、切换、关闭应用，理解窗口、菜单、对话框 |
| 第 4 课时 | 文件与文件夹 | 会新建、命名、移动、复制、删除、恢复和查找文件 |
| 第 5 课时 | 路径与扩展名 | 理解文件类型、扩展名、绝对路径和相对路径的基本含义 |
| 第 6 课时 | 键盘与快捷键 | 熟练输入英文字符，掌握常用快捷键和编程常见符号 |

### 第二阶段：理解数据和网络

重点是让学生知道计算机处理的是数据，网络传输的也是数据。

| 课时 | 主题 | 核心任务 |
|---|---|---|
| 第 7 课时 | 数据与二进制 | 理解 0 和 1、位、字节、KB、MB、GB |
| 第 8 课时 | 文本、图片和声音 | 知道文字编码、像素、分辨率、采样的基本概念 |
| 第 9 课时 | 网络和浏览器 | 理解网址、域名、IP、网页、下载、上传 |
| 第 10 课时 | 信息检索与判断 | 会用关键词搜索，能初步判断资料是否可靠 |
| 第 11 课时 | 账户、密码与隐私 | 会设置较安全密码，知道个人信息保护和网络风险 |

### 第三阶段：进入计算思维

重点是让学生学会把问题讲清楚、拆清楚、步骤化。

| 课时 | 主题 | 核心任务 |
|---|---|---|
| 第 12 课时 | 问题分解 | 把一个大任务拆成若干小任务 |
| 第 13 课时 | 抽象与建模 | 找出关键对象、属性和规则，去掉无关信息 |
| 第 14 课时 | 算法与流程图 | 用自然语言、流程图或伪代码描述解决步骤 |
| 第 15 课时 | 顺序、分支、循环 | 用生活例子理解三种基本控制结构 |
| 第 16 课时 | 调试思维 | 学会复现问题、定位步骤、逐项排查 |

### 第四阶段：衔接基础编程

重点是让学生在正式学语言前先理解程序概念。

| 课时 | 主题 | 核心任务 |
|---|---|---|
| 第 17 课时 | 程序与指令 | 理解程序是计算机可执行的一组明确指令 |
| 第 18 课时 | 输入、处理、输出 | 用 IPO 模型描述程序：Input、Process、Output |
| 第 19 课时 | 变量与表达式 | 理解变量是存放数据的名字，表达式可以计算结果 |
| 第 20 课时 | 条件判断 | 理解“如果……那么……否则……” |
| 第 21 课时 | 循环重复 | 理解有限次数循环和满足条件时循环 |
| 第 22 课时 | 函数与模块 | 理解把一组操作封装成可重复使用的功能 |
| 第 23 课时 | 测试与改错 | 用不同输入测试程序，记录错误和修改过程 |
| 第 24 课时 | 综合小项目 | 完成一个简单任务，如成绩等级判断、猜数字流程设计或自动整理文件方案 |

## 四、各模块具体应学内容

### 1. 计算机整体认识

学生需要理解：

1. 计算机是一种能够接收数据、处理数据、存储数据、输出结果的电子设备。
2. 常见计算设备包括台式机、笔记本、手机、平板、服务器、智能手表、机器人控制器等。
3. 计算机系统通常由硬件、软件、数据和用户组成。
4. 程序是告诉计算机“按什么步骤做事”的指令集合。
5. 计算机并不真正“懂人话”，它只能按照明确规则处理数据。

建议活动：

| 活动 | 目标 |
|---|---|
| 观察一台电脑的组成 | 区分显示器、键盘、鼠标、主机、接口等 |
| 比较电脑和手机 | 找出输入、处理、存储、输出的共同点 |
| 讲解“点外卖”的信息流 | 理解输入、处理、输出、反馈 |

### 2. 硬件基础

学生需要掌握的硬件概念：

| 名称 | 通俗理解 | 编程相关意义 |
|---|---|---|
| CPU | 负责计算和执行指令的核心 | 程序最终由 CPU 执行 |
| 内存 | 程序运行时临时放数据的地方 | 程序运行越复杂，越需要内存 |
| 硬盘/固态硬盘 | 长期保存文件的地方 | 代码、图片、项目文件保存在这里 |
| 输入设备 | 键盘、鼠标、麦克风、摄像头等 | 程序可以接收用户输入 |
| 输出设备 | 显示器、音箱、打印机等 | 程序可以把结果显示或播放出来 |
| 主板 | 连接各硬件的基础平台 | 帮助理解硬件之间协同工作 |
| 显卡 | 处理图形显示的硬件 | 游戏、图像、AI 计算中很重要 |
| 网卡 | 让设备连接网络 | 程序可以通过网络收发数据 |

学生不需要背复杂参数，但应理解：

1. CPU 影响计算速度。
2. 内存影响能同时运行多少程序。
3. 硬盘影响能保存多少文件。
4. 输入输出设备决定人与计算机如何交互。
5. 硬件必须由软件控制才能完成任务。

### 3. 操作系统基础

学生需要理解：

1. 操作系统是管理硬件和软件的基础软件，如 Windows、macOS、Linux、Android、iOS。
2. 应用程序需要在操作系统上运行。
3. 文件管理、窗口管理、用户账户、权限管理都由操作系统提供。
4. 程序卡住、无响应、权限不足、找不到文件，很多都与操作系统有关。

必须会做的操作：

| 操作 | 要求 |
|---|---|
| 打开和关闭应用 | 能从开始菜单、桌面、搜索或启动台打开程序 |
| 切换窗口 | 能在多个程序之间切换 |
| 安装和卸载软件 | 知道从正规来源安装，不随意安装未知软件 |
| 查看文件位置 | 能找到一个文件实际保存在哪个文件夹 |
| 修改设置 | 能调整输入法、网络、声音、显示等基本设置 |
| 处理无响应 | 能尝试等待、关闭窗口、保存工作、重新启动 |

### 4. 文件、文件夹与路径

这是编程前必须打牢的基础。很多初学者写程序遇到问题，不是语法问题，而是找不到文件、路径写错、扩展名不清楚。

学生需要掌握：

1. 文件用于保存数据，文件夹用于分类管理文件。
2. 文件名通常由“名称 + 扩展名”组成，如 `作业.docx`、`照片.jpg`、`index.html`、`main.py`。
3. 扩展名常表示文件类型，但不能保证文件内容一定正确。
4. 路径表示文件所在位置。
5. 绝对路径从磁盘或根目录开始，相对路径从当前文件夹开始。
6. 压缩包可以把多个文件打包，常见格式有 `.zip`、`.rar`、`.7z`。
7. 重要文件要备份，可以使用 U 盘、移动硬盘或云盘。

必须会做的操作：

| 操作 | 要求 |
|---|---|
| 新建文件夹 | 能按学科、日期、项目分类 |
| 规范命名 | 文件名清楚，不用“新建文档1”“最终版最终版” |
| 查找文件 | 会按名称、类型、日期搜索 |
| 显示扩展名 | 知道 `hello.py.txt` 和 `hello.py` 不是一回事 |
| 复制路径 | 会获取一个文件或文件夹的位置 |
| 解压缩文件 | 能解压后找到真正的项目文件 |

建议命名规范：

| 不推荐 | 推荐 |
|---|---|
| `作业` | `2026-信息科技-第1次作业.docx` |
| `新建文件夹` | `Python练习-变量与输入` |
| `最终版2` | `演示文稿-校园安全-v2.pptx` |

### 5. 键盘、输入与常用快捷键

编程对输入的准确性要求很高。学生需要先熟悉键盘，尤其是英文符号。

必须熟悉的英文符号：

| 符号 | 名称 | 编程中常见用途 |
|---|---|---|
| `()` | 小括号 | 函数调用、表达式分组 |
| `[]` | 中括号 | 列表、下标 |
| `{}` | 大括号 | 代码块、字典、集合 |
| `"` `'` | 引号 | 表示文本 |
| `:` | 冒号 | 条件、循环、字典等场景 |
| `;` | 分号 | 某些语言中分隔语句 |
| `,` | 逗号 | 分隔多个数据 |
| `.` | 点 | 小数点、属性访问、文件名 |
| `/` `\\` | 斜杠、反斜杠 | 路径、转义、除法 |
| `=` | 等号 | 赋值或判断相等的一部分 |
| `+` `-` `*` `/` | 运算符 | 加减乘除 |
| `<` `>` | 尖括号 | 比较大小、HTML 标签 |
| `_` | 下划线 | 变量命名 |
| `#` | 井号 | 注释、编号 |

常用快捷键：

| 快捷键 | 功能 |
|---|---|
| `Ctrl + C` / `Command + C` | 复制 |
| `Ctrl + V` / `Command + V` | 粘贴 |
| `Ctrl + X` / `Command + X` | 剪切 |
| `Ctrl + Z` / `Command + Z` | 撤销 |
| `Ctrl + S` / `Command + S` | 保存 |
| `Ctrl + A` / `Command + A` | 全选 |
| `Ctrl + F` / `Command + F` | 查找 |
| `Alt + Tab` / `Command + Tab` | 切换应用 |

学生还需要养成：

1. 输入英文代码时使用英文标点。
2. 文件名尽量避免过多空格和特殊符号。
3. 缩进要整齐，不能随意多一个或少一个空格。
4. 复制代码后要理解代码含义，不只会粘贴运行。

### 6. 数据表示基础

学生需要理解：

1. 计算机内部用二进制表示数据。
2. 一个二进制位称为 bit，只能是 0 或 1。
3. 8 个 bit 通常组成 1 个 byte，即 1 字节。
4. 常见容量单位包括 B、KB、MB、GB、TB。
5. 文本、图片、声音、视频都可以转化为数字保存。

基础概念表：

| 概念 | 说明 |
|---|---|
| bit | 最小数据单位，表示 0 或 1 |
| Byte | 字节，常用于表示文件大小 |
| KB | 约一千字节 |
| MB | 约一百万字节，常见图片、音乐文件大小 |
| GB | 约十亿字节，常见视频、软件、硬盘容量单位 |
| 编码 | 把文字变成数字规则，如 ASCII、Unicode |
| 像素 | 图片中的小点，像素越多通常越清晰 |
| 分辨率 | 图片或屏幕横向和纵向像素数量 |

建议活动：

| 活动 | 目标 |
|---|---|
| 比较文本、图片、视频文件大小 | 直观理解不同数据占用空间不同 |
| 用 0 和 1 表示开关灯 | 理解二进制和状态 |
| 放大图片观察像素 | 理解图片由像素组成 |
| 查看一个汉字和一个英文字母占用空间 | 初步理解编码差异 |

### 7. 网络基础

学生需要理解：

1. 网络让不同设备之间可以传输数据。
2. 浏览网页时，浏览器向服务器请求网页内容，服务器返回数据。
3. 网址 URL 用来定位网络资源。
4. 域名方便人记忆，IP 地址用于网络中的设备定位。
5. Wi-Fi 是无线接入网络的方式之一，不等于互联网本身。
6. 上传是从本机发送到网络，下载是从网络保存到本机。
7. 云盘、在线文档、在线编程平台本质上都依赖网络服务。

基础概念表：

| 概念 | 通俗解释 |
|---|---|
| 浏览器 | 用来访问网页的应用程序 |
| 网址 | 网络资源的地址 |
| 域名 | 便于记忆的网站名称 |
| IP 地址 | 网络中设备或服务器的位置标识 |
| 服务器 | 为其他设备提供服务的计算机 |
| 客户端 | 请求服务的设备或程序 |
| HTTP/HTTPS | 浏览器和服务器之间传输网页数据的常见规则 |
| 局域网 | 学校机房、家庭路由器下的小范围网络 |

### 8. 信息检索与资料判断

后续学习编程时，学生不可能只靠记忆，需要会查资料、看提示、找解决办法。

学生需要掌握：

1. 使用准确关键词搜索，而不是输入一整段模糊问题。
2. 能区分教程、广告、问答、文档、论坛、百科。
3. 优先参考教材、官方网站、权威机构资料和老师指定资料。
4. 对搜索结果保持怀疑，遇到矛盾信息要交叉验证。
5. 引用图片、文字、代码时要注意来源和版权。

关键词示例：

| 模糊搜索 | 更好的搜索 |
|---|---|
| `电脑坏了怎么办` | `Windows 文件打不开 docx 解决方法` |
| `python 不行` | `Python SyntaxError invalid syntax 原因` |
| `网页怎么做` | `HTML 标题 段落 图片 基础教程` |

### 9. 计算思维

计算思维是进入编程前最重要的能力。

学生需要理解四个核心方法：

| 方法 | 含义 | 示例 |
|---|---|---|
| 分解 | 把复杂问题拆成小问题 | 制作班级通讯录可拆成收集信息、整理表格、排序、保存 |
| 抽象 | 保留关键特征，去掉无关细节 | 学生成绩系统只关心姓名、学号、成绩等数据 |
| 模式识别 | 找相同规律 | 多个同类文件都按“日期-科目-标题”命名 |
| 算法 | 解决问题的明确步骤 | 判断一个数是否为偶数：输入、除以 2 看余数、输出结果 |

学生应能用自然语言描述算法，例如：

```text
任务：判断学生成绩是否及格
1. 输入成绩
2. 如果成绩大于或等于 60，输出“及格”
3. 否则，输出“不及格”
```

也应能读懂简单流程：

```text
开始
输入用户名和密码
如果用户名和密码正确
    显示登录成功
否则
    显示登录失败
结束
```

### 10. 程序基础概念

在正式学习编程语言前，学生至少要理解下面这些概念。

| 概念 | 通俗解释 | 例子 |
|---|---|---|
| 指令 | 让计算机执行的一步操作 | 显示文字、计算结果、保存文件 |
| 程序 | 多条指令按顺序组成 | 一个计算器程序 |
| 输入 | 程序接收的数据 | 用户输入姓名和成绩 |
| 输出 | 程序给出的结果 | 显示“你好，小明” |
| 变量 | 给数据起的名字 | `score` 表示成绩 |
| 常量 | 程序中不改变的值 | 圆周率、满分 100 |
| 表达式 | 能计算出结果的式子 | `price * count` |
| 顺序结构 | 按从上到下执行 | 先输入，再计算，再输出 |
| 分支结构 | 根据条件选择执行 | 如果下雨就带伞 |
| 循环结构 | 重复执行一组操作 | 连续输出 1 到 100 |
| 函数 | 把一组操作封装起来反复使用 | 计算平均分 |
| 注释 | 写给人看的说明 | 说明一段代码的作用 |
| 调试 | 找出并修改错误 | 查看哪一步结果不对 |

建议先用生活化例子引入，再过渡到代码。例如：

| 生活问题 | 编程概念 |
|---|---|
| 自动售货机投币后出饮料 | 输入、条件判断、输出 |
| 每天背 10 个单词，坚持 7 天 | 循环 |
| 计算班级平均分 | 变量、累加、除法 |
| 食堂排队点餐 | 顺序结构、选择结构 |

### 11. 调试与测试

学生需要从一开始就知道：程序出错是正常现象，关键是会查错。

常见错误类型：

| 类型 | 说明 | 示例 |
|---|---|---|
| 输入错误 | 符号、拼写、大小写或缩进不正确 | 中文括号、漏引号 |
| 逻辑错误 | 程序能运行但结果不对 | 平均分公式写错 |
| 文件错误 | 找不到文件或路径错误 | 图片放错文件夹 |
| 环境错误 | 软件版本、权限或设置问题 | 没安装运行环境 |
| 数据错误 | 输入数据格式不符合要求 | 需要数字却输入文字 |

调试基本步骤：

1. 先读错误提示，找出出现问题的行或操作。
2. 回忆刚才修改了什么。
3. 检查文件名、路径、标点、大小写和缩进。
4. 把复杂任务拆成小步骤，逐步运行。
5. 用简单数据测试，再用复杂数据测试。
6. 记录错误原因和解决方法，形成自己的错题本。

### 12. 数字安全、版权与规范

学生需要掌握：

1. 不随意泄露姓名、住址、电话、身份证号、学校、家庭信息。
2. 不点击来源不明的链接，不下载来历不明的软件。
3. 密码不要过短，不要多个重要账户共用同一密码。
4. 遇到中奖、免费皮肤、账号异常、转账付款等信息要先求证。
5. 使用网络图片、音乐、文字、代码时要尊重版权和引用规范。
6. 不用他人账号，不破解软件，不传播病毒或恶意脚本。
7. 使用 AI 工具时，要检查结果，不把 AI 生成内容直接当成事实。

## 五、重点和难点

### 重点内容

1. 文件和路径：这是后续写代码、运行项目、提交作业的基础。
2. 键盘和英文符号：编程语言对符号要求严格，中文标点常导致错误。
3. 数据表示：理解计算机为什么能处理文字、图片、声音和程序。
4. 计算思维：学会把问题拆成步骤，而不是只记代码。
5. 分支和循环：这是大多数基础程序的核心结构。
6. 调试习惯：会看错误、会复现、会逐步排查。

### 常见困难与教学对策

| 常见困难 | 教学对策 |
|---|---|
| 学生会玩电脑但不会管理文件 | 每节课都要求按固定目录保存和提交文件 |
| 分不清内存和硬盘 | 用“书桌”和“书柜”类比：内存像临时工作桌，硬盘像长期储物柜 |
| 不理解路径 | 用学校地址类比：城市、学校、楼层、教室、座位 |
| 经常输入中文标点 | 设置“编程输入检查”：括号、引号、冒号都必须是英文 |
| 一遇到报错就停止 | 建立“错误提示先读三遍”的习惯 |
| 只会照抄代码 | 先让学生用自然语言说出步骤，再写代码 |
| 搜索资料不会筛选 | 规定必须说明来源，并比较至少两个结果 |

## 六、编程前应达到的能力标准

在进入正式编程课前，学生最好达到以下标准。

### 1. 操作能力

| 能力 | 达标表现 |
|---|---|
| 文件管理 | 能独立创建项目文件夹，保存、查找、复制和压缩文件 |
| 路径理解 | 能说出一个文件大致位于哪个文件夹，知道路径写错会导致找不到文件 |
| 英文输入 | 能输入常见编程符号，能区分中英文标点 |
| 软件使用 | 能打开编辑器、浏览器、文件管理器，并在多个窗口间切换 |
| 搜索资料 | 能用关键词查找问题，并判断结果是否适合自己 |

### 2. 概念理解

| 能力 | 达标表现 |
|---|---|
| 硬件软件 | 能说出 CPU、内存、硬盘、操作系统、应用软件的作用 |
| 数据表示 | 知道计算机用 0 和 1 表示数据，理解位、字节和文件大小 |
| 网络基础 | 能说出浏览器、网址、服务器、上传、下载的含义 |
| 程序概念 | 理解程序是由明确指令组成的 |
| 控制结构 | 能用生活例子解释顺序、分支、循环 |

### 3. 思维能力

| 能力 | 达标表现 |
|---|---|
| 分解问题 | 能把一个任务拆成 3 到 5 个步骤 |
| 抽象表达 | 能找出问题中的关键数据和规则 |
| 流程描述 | 能用自然语言或流程图写出解决步骤 |
| 测试意识 | 能用不同输入检查结果是否正确 |
| 调试意识 | 出错后能尝试看提示、查位置、改一处、再测试 |

## 七、推荐小练习

### 练习 1：整理学习文件夹

任务：

1. 新建一个名为 `信息科技学习` 的文件夹。
2. 在其中建立 `课堂练习`、`作业提交`、`资料图片`、`程序代码` 四个子文件夹。
3. 新建一个文本文件，命名为 `2026-文件管理练习.txt`。
4. 写入自己的文件整理规则。
5. 将整个文件夹压缩为 `.zip` 文件。

考查点：文件夹、命名、扩展名、压缩、分类。

### 练习 2：认识文件大小

任务：

1. 找一个文本文件、一张图片、一个音频或视频文件。
2. 记录它们的文件大小。
3. 按从小到大排序。
4. 说明为什么视频通常比文本文件大。

考查点：数据大小、文件类型、文本和多媒体数据。

### 练习 3：画出登录流程图

任务：

用自然语言或流程图描述登录网站的过程：

```text
输入账号和密码
判断账号密码是否正确
如果正确，进入主页
如果错误，提示重新输入
```

考查点：输入、判断、输出、分支结构。

### 练习 4：设计自动售货机算法

任务：

描述自动售货机卖饮料的步骤：

1. 用户选择饮料。
2. 用户付款。
3. 判断付款是否足够。
4. 如果足够，出饮料并找零。
5. 如果不够，提示继续付款或取消。

考查点：顺序结构、条件判断、算法表达。

### 练习 5：成绩等级判断

任务：

写出判断成绩等级的规则：

| 分数范围 | 等级 |
|---|---|
| 90 到 100 | 优秀 |
| 80 到 89 | 良好 |
| 60 到 79 | 合格 |
| 0 到 59 | 需要努力 |

要求学生先用自然语言描述，再画流程图，最后再过渡到代码。

考查点：变量、比较、分支、边界条件。

### 练习 6：重复任务与循环

任务：

描述“输出 1 到 10”的过程：

```text
从 1 开始
每次输出当前数字
数字加 1
如果数字不超过 10，就继续
否则结束
```

考查点：循环变量、循环条件、重复执行。

## 九、教学建议

1. 先操作，后概念。让学生先完成真实任务，再总结概念名称。
2. 每节课都安排一个可交付成果，如文件夹、流程图、表格、思维导图或小程序设计稿。
3. 文件管理和输入规范要反复训练，不要只讲一次。
4. 少讲硬件参数，多讲每个部件解决什么问题。
5. 数据表示不要求深入数学证明，重点是理解“任何信息都能数字化”。
6. 计算思维要结合生活情境，不要一上来就写代码。
7. 讲分支和循环时，先用流程图和自然语言，再进入具体编程语言。
8. 对错误保持正常化态度，把报错当作学习材料。
9. 评价学生时，不只看结果，也看命名、步骤、文件组织、调试记录。
10. 可以把 AI 工具作为信息检索和思路辅助工具，但要强调核查、引用和独立理解。

## 十、最小必学清单

如果课时有限，至少应保证学生掌握以下内容：

1. 计算机系统：硬件、软件、数据、网络的基本关系。
2. 文件管理：文件夹、文件名、扩展名、路径、压缩和备份。
3. 键盘输入：英文标点、常用快捷键、缩进和保存。
4. 数据基础：二进制、位、字节、文件大小、文字和图片的数字化。
5. 网络基础：浏览器、网址、服务器、上传、下载、网络安全。
6. 计算思维：分解、抽象、算法、流程图。
7. 程序基础：输入、输出、变量、顺序、分支、循环、函数。
8. 调试习惯：读提示、查位置、逐步测试、记录错误。

学完这些内容后，学生再进入 Scratch、Python、HTML/CSS/JavaScript 或机器人编程，会更容易理解“为什么这样写”，而不是只机械模仿代码。
