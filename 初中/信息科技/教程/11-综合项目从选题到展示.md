# 11-综合项目：从选题到展示

综合项目是信息科技入门学习的收束。它不是只看你写了多少代码，而是看你能不能独立经历完整过程：选题、分析、设计、实现、测试、整理、展示和反思。

---

## 一、学习目标

学完本节，你应该能做到：

1. 选择一个适合自己能力的小项目。
2. 写出项目需求和 IPO 分析。
3. 画流程图或写伪代码。
4. 从最小可运行版本开始实现。
5. 使用测试数据检查功能。
6. 记录错误和修改过程。
7. 整理项目文件并压缩提交。
8. 向别人展示作品并说明思路。

---

## 二、综合项目可以做什么

综合项目不需要特别大，关键是完整、清楚、能运行、能解释。

### 推荐项目

| 项目 | 难度 | 适合工具 | 核心知识 |
|---|---|---|---|
| 成绩等级判断器 | 入门 | Python | 输入、数字转换、条件判断 |
| 奇偶数判断器 | 入门 | Python | 取余、分支 |
| 简易计算器 | 入门 | Python 或网页 | 输入、表达式、条件 |
| 猜数字游戏 | 入门 | Python | 循环、分支、变量 |
| 问答计分系统 | 基础 | Python 或图形化编程 | 变量、分支、循环 |
| 单词记忆小助手 | 基础 | Python | 列表、循环、字符串 |
| 班级兴趣统计 | 基础 | Python | 列表、统计、输出 |
| 校园安全宣传网页 | 基础 | HTML/CSS/JavaScript | 网页结构、样式、交互 |
| 校园文明互动动画 | 基础 | 图形化编程 | 事件、对话、场景切换 |
| 倒计时提醒器 | 提高 | micro:bit 或机器人平台 | 输入、输出、循环、事件 |

### 选题原则

好项目应该满足：

1. 主题清楚。
2. 功能不太多。
3. 自己能解释。
4. 能在规定时间内完成。
5. 可以准备测试数据。
6. 不涉及隐私、攻击、作弊或破坏系统。

不推荐选题：

- 功能太大，例如“做一个完整社交软件”。
- 自己完全不理解，只能复制。
- 需要大量复杂素材。
- 需要访问不安全网站或输入隐私信息。

## 三、项目流程总览

```text
选题
→ 需求分析
→ IPO 分析
→ 流程图或伪代码
→ 最小版本
→ 增加功能
→ 测试与调试
→ 整理提交
→ 展示反思
```

每一步都要有产出。

| 步骤 | 学生要做什么 | 产出 |
|---|---|---|
| 选题 | 选择能完成的小问题 | 项目题目 |
| 需求分析 | 说明给谁用、解决什么问题 | 需求说明 |
| IPO 分析 | 写清输入、处理、输出 | IPO 表 |
| 设计 | 写流程图或伪代码 | 设计稿 |
| 实现 | 分步骤编写程序或网页 | 作品文件 |
| 测试 | 用多组数据检查结果 | 测试记录 |
| 调试 | 记录错误和修改方法 | 修改记录 |
| 整理 | 规范命名、压缩项目 | 提交包 |
| 展示 | 说明功能、思路、亮点、不足 | 展示稿或口头汇报 |

## 四、第一步：选题

### 1. 从生活中找问题

可以从这些方向思考：

| 方向 | 可能项目 |
|---|---|
| 学习 | 单词记忆、成绩等级、错题记录 |
| 生活 | 购物计算、时间换算、倒计时 |
| 校园 | 校园安全宣传、班级兴趣统计 |
| 游戏 | 猜数字、问答计分、迷宫 |
| 展示 | 个人介绍页、兴趣展示页 |
| 硬件 | 光线提醒器、倒计时提醒器 |

### 2. 控制项目范围

把项目分成“必须完成”和“可以拓展”。

示例：猜数字游戏。

| 类型 | 功能 |
|---|---|
| 必须完成 | 用户输入数字，猜错继续，猜对结束 |
| 可以拓展 | 提示太大太小、统计次数、随机数字、限制次数 |

先完成必须功能，再考虑拓展。

## 五、第二步：需求分析

需求分析就是说清楚作品要做什么，不做什么。

### 示例：问答计分系统

项目名称：信息科技知识问答。

目标用户：学习信息科技的初中学生。

必须功能：

1. 显示题目。
2. 接收用户答案。
3. 判断对错。
4. 答对加分。
5. 最后显示总分。

暂不做：

1. 登录账号。
2. 保存历史成绩。
3. 排行榜。
4. 联网对战。

这样可以避免项目过大。

---

## 六、第三步：IPO 分析

继续以问答计分系统为例。

| 项目 | 内容 |
|---|---|
| 输入 | 用户对每道题的答案 |
| 处理 | 与正确答案比较；正确则加分 |
| 输出 | 每题对错提示；最终总分 |

再写可能用到的数据：

| 数据 | 用途 |
|---|---|
| `questions` | 保存题目列表 |
| `answers` | 保存答案列表 |
| `score` | 保存得分 |
| `user_answer` | 保存用户当前答案 |

## 七、第四步：流程图或伪代码

如果不会画流程图，可以先写伪代码。

### 问答计分系统伪代码

```text
开始
设置 score = 0
准备题目列表和答案列表
从第 1 题开始循环
    显示题目
    输入用户答案
    如果用户答案等于正确答案
        显示答对
        score 加 1
    否则
        显示答错和正确答案
显示最终得分
结束
```

### 猜数字游戏伪代码

```text
开始
设置秘密数字
设置猜测次数为 0
输入用户猜测
次数加 1
当用户猜测不等于秘密数字时
    如果猜测太大
        显示太大
    否则
        显示太小
    再次输入用户猜测
    次数加 1
显示猜对和次数
结束
```

## 八、第五步：实现最小版本

最小版本就是“功能最少但能运行”的版本。

### 为什么要先做最小版本

1. 更容易成功。
2. 更容易发现错误。
3. 不会因为功能太多而做不完。
4. 后面可以逐步增加功能。

### 示例：猜数字游戏版本规划

| 版本 | 功能 |
|---|---|
| v1 | 固定秘密数字，猜错继续，猜对结束 |
| v2 | 增加太大或太小提示 |
| v3 | 增加猜测次数统计 |
| v4 | 改成随机秘密数字 |
| v5 | 限制最多猜 5 次 |

每完成一个版本都要保存和测试。

| 2 |  |  |  |  |  |

### 2. 必须测试三类情况

| 类型 | 说明 | 示例 |
|---|---|---|
| 正常情况 | 常见输入 | 成绩 85、猜数字 7 |
| 边界情况 | 分界线附近 | 成绩 60、90、0、100 |
| 特殊情况 | 容易出错 | 除数为 0、答案为空、路径错误 |

### 3. 调试记录表

| 问题 | 出现位置 | 原因 | 修改方法 | 是否解决 |
|---|---|---|---|---|
|  |  |  |  |  |

### 4. 调试原则

1. 先复现问题。
2. 读错误提示。
3. 找最近修改过的地方。
4. 一次只改一个地方。
5. 改完马上测试。
6. 把原因和方法写下来。

## 十一、第八步：展示作品

展示时不要只说“这是我的作品”。要按结构讲。

### 展示顺序

```text
1. 项目名称
2. 为什么做这个项目
3. 作品能做什么
4. 使用了哪些知识
5. 演示运行过程
6. 测试过哪些情况
7. 遇到什么问题，怎么解决
8. 还有什么不足和改进想法
```
